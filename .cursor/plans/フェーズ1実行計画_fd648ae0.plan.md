# フェーズ1: プロジェクト基盤構築とデータベース設計

以下の手順でフェーズ1を実行します。

## 1. Bun Workspacesを用いたモノレポ構成の初期化
- プロジェクトルートに `package.json` を作成し、Bun Workspacesの設定（`"workspaces": ["apps/*", "packages/*"]`）を追加します。
- 必要なディレクトリ構造（`apps/web`, `apps/cli`, `packages/shared`）を作成します。
- プロジェクトルートに `.env` と `.env.example` を作成し、SupabaseのURLやキーなどの環境変数を管理する基盤を整えます。

## 2. Nuxt.js + Nitroプロジェクトのセットアップ
- `apps/web` ディレクトリ内でNuxt 3の初期化コマンド（`npx nuxi@latest init .` または `bunx nuxi init .`）を実行し、フロントエンドおよびAPIの基盤を作成します。

## 3. Supabaseスキーマ定義の適用
- 既に作成済みのSupabaseプロジェクト（[https://nsgiyvjmdlehcdkpaunu.supabase.co](https://nsgiyvjmdlehcdkpaunu.supabase.co)）に対して、Supabase CLIを使用してデータベーススキーマを適用します。
- `supabase init` でプロジェクトを初期化し、`supabase link` で既存のプロジェクトに接続します。
- `supabase migration new init_schema` コマンドでマイグレーションファイルを作成し、`docs/SCHEMA.md` に記載されているSQLを記述します。
- `supabase db push` を実行して、リモートのSupabaseプロジェクトにスキーマを反映させます。
- 反映後、`supabase gen types typescript` を使用してデータベースの型定義を自動生成し、`packages/shared` 側で活用できるようにするのも検討します。

## 4. 共通型定義の作成
- `packages/shared` 内に `package.json` と `index.ts`（または `types/index.ts`）を作成します。
- `docs/SCHEMA.md` の定義に基づき、データベースの各テーブルに対応するTypeScriptのインターフェース（`Task`, `List`, `Status`, `PersonalAccessToken`, `PushSubscription` など）を実装し、`apps/web` および `apps/cli` から参照できるようにエクスポートします。
