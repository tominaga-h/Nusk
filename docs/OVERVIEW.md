# 次世代タスク管理システム「Nusk」 要件定義書

## 1. プロジェクト概要

### 1.1. 背景と目的

既存のタスク管理ツール（Markdown、Notion、スマホアプリ、スプレッドシート等）における「手動移動の苦痛」「入力の摩擦」「リマインドの欠如」という課題を解決する。
エンジニアの思考とワークフローに最適化され、摩擦ゼロの入力と確実な実行をサポートする次世代のタスク管理システム「Nusk」を構築する。

### 1.2. コアコンセプト

- **APIファースト:** Nuxt上に構築したAPIをハブとし、多様なインターフェースから一元的にタスクを操作する。
- **爆速入力 (Capture):** 作業中のコンテキストを壊さず、CLIやWebから即座にタスクを登録できる。
- **柔軟な整理 (Process):** スプシライクな柔軟なメタデータと、リストごとの状態管理を実現する。
- **確実な実行 (Do):** スマホPWAへのプッシュ通知と、未完了タスクの自動リスケジュールで「忘れ」を防止する。

### 1.3. システムアーキテクチャ・技術スタック

- **フロントエンド & APIサーバー:** Nuxt.js (Vue.js, TypeScript) + Nitro
- **インフラ・デプロイ:** Vercel
- **データベース & 認証:** Supabase (PostgreSQL, Google OAuth)
- **CLIツール:** Go (Cobra等によるシングルバイナリ)

---

## 2. 構築物とディレクトリ構成

本プロジェクトで開発・提供するクライアントは以下の通り。言語やデプロイサイクルが異なるため、リポジトリ直下でフォルダを分割するモノレポ風の構成とする。

### 2.1. ディレクトリ構成（想定）

```txt
nusk/
├── web/ （Nuxt.jsプロジェクト: フロントエンド + API。Vercelへデプロイ）
└── cli/ （Goプロジェクト: ターミナル用CLIツール。ローカルでビルド）
```

### 2.2. 各クライアントの役割

1. **レスポンシブWebサイト（PWA対応）: `web/`**
   - メインの操作インターフェース。PCブラウザでの詳細なタスク整理と、スマホでのアプリライクな閲覧・通知受信を担う。
2. **CLIツール: `cli/`**
   - エンジニアのPC作業に特化した、ターミナルからの爆速タスク入力特化型ツール。コマンド名は `nusk` とする。

---

## 3. Webサイト（PWA）の要件

### 3.1. タスク操作・管理（CRUD）機能

- Web画面上からタスクの新規登録、編集、削除、ステータス変更がスムーズに行えること。
- Inbox（未整理）に溜まったタスクを適切なリストへ振り分け、メタデータを付与できること。

### 3.2. タスク閲覧・UI機能

- **リストView:** プロジェクトやカテゴリ（Inbox、仕事、プライベート等）ごとにタスクを一覧表示する。
- **日付View:** 「Today」「Tomorrow」など、`scheduled_date` (着手予定日) に基づいてタスクを表示する。リストの枠を超えて「今日やること」に集中できる。
- **ワンタップ着手日変更:** UI上の「今日やる」「明日やる」ボタンで、タスクの `scheduled_date` を即座に更新できる。

### 3.3. タスクの状態・メタデータ管理

- **状態 (Status) のリスト単位管理:** 「未対応」「対応中」「完了」などの状態は、リスト（箱）ごとに自由に定義・変更できる。
- **拡張メタデータ:** カテゴリやタグ、重要度など、ユーザー個人が自由に拡張したい項目はDBの `JSONB` カラムに保存し、Web UIから柔軟に追加・編集・閲覧可能とする。

### 3.4. 自動化・リマインド機能

- **自動リスケジュール (Overdue処理):** `scheduled_date` が過去のまま未完了となっているタスクは、深夜のバッチ処理または画面アクセス時に自動的に「今日 (Today)」にリスケジュールされる。
- **繰り返しタスクのクローン生成:** 繰り返しルールが設定されたタスクが「完了」状態になった際、元のタスクは履歴として残し、次回の期日がセットされた新しいタスクを自動生成する。
- **プッシュ通知:** タスクに設定されたリマインド時間に基づき、PWAを通じてスマホへWeb Push通知を送信する。

### 3.5. システム・設定機能

- Supabaseを通じたGoogle OAuthでのログイン。
- CLIツール等からAPIを利用するための「パーソナルアクセストークン」の発行・管理画面。

---

## 4. CLIツールの要件

### 4.1. 爆速タスク入力機能

- ターミナルから `nusk add "タスク名"` を実行することで、API経由で「Inbox」リストにタスクを即座に登録する。
- 引数なしで `nusk add` を実行した場合、環境変数 `$EDITOR` (Vim/NeoVim等) が起動し、保存（`:wq` 等）と同時にタスクとして登録される。
- 登録完了時のレスポンスは0.1秒以内を目指し、思考を妨げない。

### 4.2. API連携

- Webサイト側で発行したアクセストークンをローカルの設定ファイル等に保持し、NuxtのAPIサーバーを安全に呼び出す。

---

## 5. データモデル (DBスキーマ概要)

- **users:** ユーザー情報 (Supabase Auth連携)
- **lists (箱):** `id`, `user_id`, `name`, `is_inbox` (boolean)
- **statuses (状態):** `id`, `list_id` (リストに紐付け), `name`, `category` (内部判定用), `sort_order`
- **tasks (タスク):**
  - `id`, `user_id`, `list_id`, `status_id`, `title`
  - `scheduled_date` (着手予定日)
  - `reminder_time` (リマインド日時)
  - `recurrence_rule` (繰り返しルール)
  - `metadata` (JSONB型: 独自のタグやカテゴリを格納)
  - `created_at`, `updated_at`
