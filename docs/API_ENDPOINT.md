# Nusk API エンドポイント定義 (v1)

## 共通仕様

- **Base URL:** `/api/v1`
- **認証:** リクエストヘッダに `Authorization: Bearer <token>` を付与（CLI用のパーソナルアクセストークン、またはWebのSupabaseセッション）
- **リクエスト/レスポンス形式:** `application/json`

---

## タスクの登録

- メソッド: POST
- エンドポイント: `/api/v1/tasks`

**機能**
CLIからの `nusk add` やWeb画面からの新規作成で使用するエンドポイント。
リクエストのペイロードに `list_id` が未指定の場合は、API側で自動的に「Inbox（未整理）」のリストIDを割り当てる仕様とする。

## タスクの更新（論理削除含む）

- メソッド: PATCH
- エンドポイント: `/api/v1/tasks/:id`

**機能**
ステータス変更、着手日（`scheduled_date`）変更、メタデータ（`metadata`）の編集で使用する部分更新エンドポイント。
※物理削除（DELETE）はシステムとして廃止しているため、タスクの「削除」操作もこのエンドポイントを利用し、ステータスを「削除済み（アーカイブ）」等に変更する論理削除として扱う。

## タスク一覧の取得

- メソッド: GET
- エンドポイント: `/api/v1/tasks`

**機能**
Web画面の「リストView」や「日付View」を描画する際の一覧取得エンドポイント。
`?scheduled_date=YYYY-MM-DD` や `?list_id=xxx` などのクエリパラメータを付与することで、表示したい条件に合わせた柔軟なフィルタリングを行う。

## 特定タスクの詳細取得

- メソッド: GET
- エンドポイント: `/api/v1/tasks/:id`

**機能**
タスクの詳細画面（Webのドロワーやモーダル等）を開いた際や、CLIで特定タスクの詳細を確認する際のデータフェッチで使用するエンドポイント。JSONB型のメタデータを含む、該当タスクの全情報を取得する。
